# Building the Power BI report (about 1–2 hours)

A `.pbix` is a binary produced by Power BI Desktop, so it cannot be generated by the pipeline.
The pipeline gives you everything Power BI needs, already cleaned and modelled, so the report is
assembly rather than data work. All CSVs here are written by `python pipeline/run_analysis.py`.

> Power BI "Publish to web" requires a paid licence, so this project does not embed the live report
> on the website. Export screenshots of the three pages into `docs/` and link them from the README.

## 1. Import (Get data → Text/CSV, each file; "Load")

| File | Role |
|---|---|
| `fact_order_items.csv` | fact, one row per item in a delivered order |
| `fact_orders.csv` | order grain (use for review/lateness KPIs: avoids counting multi-item orders repeatedly) |
| `dim_customers.csv`, `dim_sellers.csv`, `dim_products.csv`, `dim_dates.csv` | dimensions |
| `v_late_attribution.csv` | late orders with `delay_attribution` (seller_delay / carrier_delay / both_or_neither) |
| `v_state_lane.csv` | seller_state × customer_state transit matrix |
| `v_seller_watchlist.csv` | seller segments + revenue at risk |
| `v_delivery_kpis.csv` | pre-aggregated KPIs by category/state |

Apply the theme: **View → Themes → Browse for themes → `olist_theme.json`**.

## 2. Model (Model view)

1. Add a date column to `fact_orders` in Power Query: `Date.From([order_purchase_timestamp])` named `purchase_date`; set data type Date.
2. Relationships (all many-to-one, single direction):
   - `fact_orders[purchase_date]` → `dim_dates[date_key]`
   - `fact_orders[customer_id]` → `dim_customers[customer_id]`
   - `fact_orders[seller_id]` → `dim_sellers[seller_id]`
   - `fact_order_items[product_id]` → `dim_products[product_id]`
   - `v_seller_watchlist[seller_id]` → `dim_sellers[seller_id]`
3. Mark `dim_dates` as a date table on `date_key`.

## 3. Measures (use `fact_orders` so every measure is one-row-per-order)

```DAX
Orders = COUNTROWS(fact_orders)

Late Orders = CALCULATE([Orders], fact_orders[was_late] = TRUE())

Pct Late = DIVIDE([Late Orders], [Orders])

On-time % = 1 - [Pct Late]

Avg Review = AVERAGE(fact_orders[review_score])

Avg Days Late (late only) =
    CALCULATE(AVERAGE(fact_orders[days_late]), fact_orders[was_late] = TRUE())

Revenue at Risk =
    CALCULATE(SUM(fact_orders[order_price]), fact_orders[was_late] = TRUE())

Hidden-Risk Revenue at Risk =
    CALCULATE(
        [Revenue at Risk],
        TREATAS(
            VALUES(v_seller_watchlist[seller_id]),
            fact_orders[seller_id]
        ),
        v_seller_watchlist[segment] = "Hidden risks"
    )

Share of Late Orders (attribution) =
    DIVIDE(COUNTROWS(v_late_attribution),
           CALCULATE(COUNTROWS(v_late_attribution), ALL(v_late_attribution[delay_attribution])))
```

Data-quality filter: add a page-level filter `flag_missing_delivery_ts = FALSE` on `fact_orders`.
Bad-timestamp orders (`flag_bad_timestamp`) are already excluded from `v_late_attribution`.

## 4. Pages

**Page 1 – Executive overview.** Cards: `Orders`, `On-time %`, `Avg Review`, `Avg Days Late (late only)`.
Line: `On-time %` by `dim_dates[year_month]`. Filled map or ranked bar: `Avg Review` by `customer_state`.
Text box with the headline from the website (generated numbers: see `site/data/results.json`).

**Page 2 – Delivery root cause.** Clustered bar: `Share of Late Orders (attribution)` by
`delay_attribution`. Matrix: rows `seller_state`, columns `customer_state`, values `avg_transit_days`
from `v_state_lane` with conditional background (blue gradient), filter `n_orders >= 30`.
Scatter: `avg_dispatch` (x) vs `avg_review` (y), size `n_orders`, details `seller_id` from `v_seller_watchlist`.
Bar: top 10 `product_category_english` by `Pct Late` (Top N filter, `Orders >= 100`).

**Page 3 – Seller scorecard.** Table from `v_seller_watchlist`: `seller_id`, `segment`, `n_orders`,
`pct_late`, `avg_review`, `revenue_at_risk` (sort desc). Donut/bar: sellers and GMV by `segment`.
Create a drill-through page "Seller detail" with `seller_id` as the drill-through field showing orders over
time and `avg_dispatch`.

**All pages.** Slicers for `dim_dates[date_key]` (between), `dim_customers[customer_state]`,
`dim_products[product_category_english]`; sync them (View → Sync slicers).
